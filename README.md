# future-price — منصة تسعير اشتراكات مركز رواد المستقبل للأطفال

منصة ثابتة تحسب **السعر العادل** لأي دوام من أسعار باقات المركز المعلنة، وتعرض التركيبة الأقل تكلفة
مع تفصيلها. كل مبلغ ورابط مصدره `data/packages.json` — لا سعر مكتوب في الكود.

**الرابط:** <https://future-price.pages.dev>

| الصفحة | الرابط | الاستخدام |
| --- | --- | --- |
| الأداة الداخلية (المعتمدة) | `/` | محادثة من أربع خطوات مع رجوع، للإدارة. بلا اختيار فترة وبلا أزرار شراء. |
| **حاسبة العرض المؤقت** | `/promo/` | نفس المحادثة بسياسة تسعير مختلفة: خصم تحفيزي على الساعات غير الرسمية. |
| نسخة الأهالي | `/parents/` | عدّادات (±) + اختيار الفترة + رابط شراء لكل عنصر + جدول مقارنة. |
| نسخة التضمين | `/embed/` | نفس نسخة الأهالي بلا ترويسة/تذييل، للصقها داخل صفحة في متجر سلة. |

نسخة الأهالي تحفظ حالتها في الرابط (`?h=6&d=5&w=4&k=1&p=m`)، فيمكن إرسال تسعيرة جاهزة كرابط.
الصفحة الرئيسية فيها حبّة ذهبية أعلى الصفحة تنقل إلى حاسبة العرض والعكس.

## القواعد المعتمدة من العميل

| القاعدة | القيمة |
| --- | --- |
| الأسبوع | أسبوع تقويمي = حتى **5 أيام** دوام |
| الشهر | **4 أسابيع** (= 20 يوم دوام عند 5 أيام أسبوعياً) |
| الترم | **4 أشهر = 16 أسبوعاً** |
| حضور جزئي | **لا خصم** — الباقة بسعرها كاملاً |
| ساعات بين الشرائح (7 أو 9) | **لا تجزئة** — ترقية لأقرب باقة أعلى (7→8، 9→10) |
| خصم الأخوة | **10%** من طفلين فأكثر |
| سعر الساعة المفردة | 25 ريال (`hourlyRate`) |

### الخوارزمية

1. لكل نوع اشتراك (`day` · `week` · `month` · `term`) تُحسب أقل تكلفة لوحدة واحدة:
   أرخص شريحة **تساوي أو تتجاوز** ساعات الطفل، مقارنةً بالحساب بالساعة (`h × 25 × أيام الوحدة`).
   إن فاز مسار الساعة فالوحدة `tier = null`.
2. برمجة ديناميكية تغطي `أيام الأسبوع × عدد الأسابيع` بأقل تكلفة (يُسمح بالتغطية الزائدة)، ثم تُتتبَّع
   الاختيارات لبناء السلة.
3. `الإجمالي = التكلفة × عدد الأطفال`، ثم خصم 10% من طفلين، ثم الصافي.

**قاعدة عرض حرجة:** أي وحدة سعرها من مسار الساعة (`tier === null`) تُسمّى «اشتراك بالساعة» فقط،
ولا تظهر في جدول المقارنة — لأن هذه الباقة غير موجودة بذلك السعر.

## العرض التحفيزي المؤقت (`/promo/`)

سياسة تسعير ثانية مستقلة تماماً، هدفها تحفيز التسجيل على الدوام القليل. السياسة كلها في
`data/promo.json` — والقاعدة تُشتق من `packages.json`، فلا قائمة ساعات مكتوبة يدوياً في أي مكان.

| الحالة | المعاملة |
| --- | --- |
| ساعات لها باقة معلنة في دليل الأسعار (4/5/6/8/10) | **باقة رسمية — سعرها كما هو، بلا أي مساس** |
| ساعات تُرقَّى إلى باقة أعلى مما يحتاجه الطفل (2/3/7/9) | **باقة غير رسمية — خصم `off`% (افتراضياً 15%)** |
| الحساب بالساعة (25 ريال) | سعر معلن رسمي مقابل ما يُستخدَم بالضبط — لا خصم (`applyToHourly`) |
| خصم الأخوة 10% | يُطبَّق بعد ذلك كالمعتاد |

التقريب: `roundTo: 5` و`roundMode: "floor"` — أي خصم 15% ثم تقريب لأسفل لأقرب 5 ريالات،
فالخصم الفعلي **لا ينزل تحت 15% أبداً**. مثال العميل: 3 ساعات × 3 أيام × شهر = 650 معلن ←
650 × 0.85 = 552.5 ← **550**.

**العرض خصم على نفس التركيبة المعتمدة، لا إعادة حساب.** لو أُعيد تشغيل البرمجة الديناميكية على
الأسعار المخفَّضة لانقلب الاشتراك الشهري أحياناً إلى 12 اشتراكاً يومياً بسبب التقريب — وهو عكس
هدف العرض. فالمحرك يأخذ التركيبة التي تختارها الأداة الرسمية ويخصم من أسعار عناصرها.

سعر العرض غير موجود كمنتج في المتجر، لذلك **لا يحمل أي رابط شراء** — يُفعَّل عبر الإدارة.
لإيقاف العرض كلياً: `"active": false` في `data/promo.json` (يختفي الرابط وتعود الأسعار المعلنة).

## البنية

```
data/packages.json     مصدر الحقيقة الوحيد للأسعار والروابط وبيانات التواصل
data/promo.json        سياسة العرض التحفيزي المؤقت (نسبة · تقريب · تجاوزات)
src/calc.js            محرك التسعير المعتمد (وحدة ES تعمل في المتصفح وفي Node بلا تعديل)
src/promo.js           محرك العرض المؤقت — يبني على calc.js ولا ينسخ منطقه
src/ui.js              مساعدات DOM صغيرة
src/chat.js            هيكل المحادثة المشترك (startChat)
src/chat-main.js       مدخل الأداة الرسمية · src/chat-promo.js مدخل العرض المؤقت
src/counters.js        واجهة العدّادات (نسخة الأهالي والتضمين)
src/styles.css         رموز التصميم والأنماط
src/build.mjs          يولّد site/ من الـJSON
src/verify.mjs         130 فحصاً: المحركان + الروابط + المخرجات + أهداف اللمس
src/serve.mjs          خادم تطوير محلي
site/                  ناتج البناء (غير مُتتبَّع في git — يُبنى في CI)
```

`src/verify.mjs` لا يكتفي بأمثلة التحقق، بل يقارن المحرك ببحث شامل مستقل في 600 حالة، ويمسح
**12,800 تركيبة** (فترتان × 10 ساعات × 5 أيام × 32 أسبوعاً × 4 أطفال) للتأكد من أن كل رابط معروض
موجود حرفياً في `packages.json`، وأن التركيبة المختارة ليست أغلى من أي بديل معروض، وأن أي مبلغ
من مسار الساعة لا يحمل اسم باقة.

## التشغيل

```bash
npm run check   # بناء + 130 فحصاً
npm run serve   # http://localhost:4173
npm run deploy  # بناء + تحقق + نشر إنتاجي على Cloudflare Pages
```

المشروع **بلا اعتماديات** — Node 22 وحدات مدمجة فقط.

## النشر

الدفع إلى `main` ينشر إنتاجياً على `future-price.pages.dev`، والدفع إلى أي فرع آخر ينتج رابط معاينة
مستقلاً. يحتاج المستودع سرّين في Settings → Secrets and variables → Actions:
`CLOUDFLARE_API_TOKEN` (صلاحية Cloudflare Pages: Edit) و`CLOUDFLARE_ACCOUNT_ID`.

## تحديث الأسعار

عدّل `data/packages.json` فقط، ثم `npm run check`. أي سعر أو رابط جديد يسري على الصفحات الثلاث
دفعة واحدة، ويرفض التحقق أي رابط لا يطابق الملف.

الأصل التصميمي في `design_handoff_calculator/` (نماذج HTML عالية الدقة + كراسة التسليم).
